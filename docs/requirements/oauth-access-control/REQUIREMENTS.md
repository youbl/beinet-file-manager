## 1. 背景与目标

项目为 Spring Boot 多模块文件管理应用，前端使用 Vue 2，页面必须继续放在 `beinet-deployment/beinet-dp-admin` 中。需要以 Google / GitHub 身份登录，并仅允许指定邮箱访问；除必要登录及静态资源路径外，其余业务页面和接口默认要求登录。

同时需补齐项目问题分析、面向 GitHub 用户的 README、完整部署步骤、一次性最终建库 SQL，以及可以定位登录失败的页面提示和服务日志。Nexscope 前后端项目仅作为实现思路参考，不引入独立前端部署或更换 Vue 2。

## 2. 角色与业务范围

| 角色 | 权限 |
| --- | --- |
| 匿名访客 | 查看登录页、加载必要资源、获取启用的供应商、发起并完成 OAuth 回调 |
| 普通用户 | 供应商验证邮箱且邮箱获准后，使用受保护的文件管理功能 |
| 管理员 | `admin-emails` 中的用户，自动拥有登录资格，并可访问受保护的管理功能 |
| 部署管理员 | 配置 OAuth、数据库、域名、邮箱列表、目录权限及服务运行环境 |

普通用户共享配置中的文件目录。当前需求不包含按用户隔离文件、租户目录权限、用户自助注册密码、邮箱绑定或跨供应商账号合并。

## 3. 功能需求

### FR-01 项目分析与可读文档

输出项目架构、Bug、安全问题及修复建议分析；README 包含用途、模块、构建、配置、登录和部署入口。历史风险报告需区分问题基线与已实现变更，不承诺所有文件管理风险均已修复。

### FR-02 Google / GitHub 登录

1. 使用服务端授权码流程；Google 和 GitHub 均使用 OAuth2，Google 身份从后端调用的 HTTPS 用户信息接口获取。
2. 登录页仅展示配置完整的供应商。Client ID 和 Secret 均为空则隐藏；只配置其中一项则阻止启动。
3. 成功登录建立服务端 Session，跳转到合法的本站业务页面；没有合法回跳地址时进入文件管理页。
4. Google 要求邮箱已验证；GitHub 从邮箱接口选取已验证且获准的邮箱，优先主邮箱，支持私有邮箱。
5. 供应商拒绝授权、状态校验失败、邮箱不获准、账号不可用或数据库失败均不建立业务登录状态。
6. 两个供应商使用相同邮箱不自动合并，本地身份以供应商和供应商用户标识确定。

### FR-03 邮箱准入与管理员

有效登录名单为 `auth.allowed-emails ∪ auth.admin-emails`。管理员无需在 allowed-emails 重复填写；这是运行时有效规则，不回写 YML 文件。

- 邮箱匹配忽略大小写与首尾空白，采用精确匹配。
- 不支持域名通配符、任意邮箱自动批准或 Gmail 别名合并。
- 两个列表均为空时拒绝所有用户；只有管理员列表非空时允许相应管理员登录。
- 管理员仍需通过供应商邮箱验证和本地账号状态校验。
- 管理员角色来自 YML；数据库 `isAdmin` 字段不授予当前管理员权限。
- 修改 YML 后重启生效；配置不提供热更新接口。

### FR-04 匿名访问默认拒绝

业务访问控制统一放在 `autoConfig.AuthorizationFilter`，用顺序 if/return 表达规则；完全移除 Spring Security。普通 Controller 负责 OAuth 和退出，HttpSession 保存本站身份，过滤器负责全部访问控制与 CSRF。

允许匿名 GET/HEAD：`/login.html`、`/auth/providers`、`/favicon.ico`、`/res/**`、两种供应商的授权发起与回调地址。

业务 HTML 即使存放在 static 目录中，也必须登录。Swagger、健康检查、文件列表、上传、下载和预览不加入匿名放行名单。

- 匿名 GET/HEAD 的 `/` 或业务 HTML：302 跳转登录页。
- 匿名业务 API：401，不返回业务数据。
- 匿名写请求不能绕过 CSRF 或身份验证。
- 不接受客户端伪造用户 ID Header 或旧 JWT 作为身份凭据。
- 无开发环境匿名绕过开关。

自定义过滤器默认跳过容器内部 ERROR/ASYNC 二次派发，具体执行次序见技术文档；它不等于公开业务 `/error` 请求或任意接口。

### FR-05 登录后持续校验

对到达业务鉴权阶段的受保护请求，应检查 Session 的 LoginUser 中本地用户 ID、有效邮箱名单及数据库账号状态。用户必须存在，且 `status=1`、`delflag=0`。

不满足条件时清除登录会话，API 返回 401，业务 HTML 跳登录。数据库校验异常时返回 503，不降级为允许访问。管理员权限在请求中根据配置重新判断。

### FR-06 管理功能与危险入口

管理员范围包括用户管理、阿里云、AWS、工具、配置及审计路径；具体匹配规则见技术文档。

旧登录/回调示例、演示页、在线解密、RAR 解压、目录提级等已停用入口对管理员也不重新开放。用户管理删除采用软删除，保留第三方身份关联，避免被删除账号重新注册绕过限制。

### FR-07 会话、CSRF 与退出

- 认证使用服务端会话及 HttpOnly Cookie，默认闲置 8 小时过期。
- HTTPS Cookie 使用 Secure、SameSite=Lax；本机 HTTP 需要显式关闭认证 Cookie 的 Secure。
- 写请求使用 `XSRF-TOKEN` Cookie 和 `X-XSRF-TOKEN` Header，前端 Axios 与 Element UI 上传均适配。
- 页面显示当前邮箱和退出入口；401 转登录，403 不应循环登录。
- POST `/auth/logout` 校验 CSRF 后销毁本地会话，清除认证上下文与相关 Cookie。
- 退出本站不等同于退出 Google/GitHub 账号或撤销其全部授权。

### FR-08 配置统一

供应商配置统一为 `auth.google.client-id/client-secret` 和 `auth.github.client-id/client-secret`。代码不再读取顶层 `github.client-id/client-secret`；Google 同样使用 auth 配置命名空间。历史环境文件不作为生产凭据来源。

公网地址使用 `auth.base-url`；回调与其协议、主机、端口一致。公网要求 HTTPS，本机允许 localhost/127.0.0.1 HTTP。不支持子路径部署。

### FR-09 页面错误诊断

登录失败页展示受控错误类型、可操作的排查建议及排查编号。覆盖会话丢失/过期、state、供应商授权/换票/资料读取、邮箱验证和准入、本地禁用及存储失败等情况。

错误详情不直接拼接原始供应商响应或数据库异常到页面。无法分类时展示通用错误，并可按编号在服务日志查找。

### FR-10 登录日志

成功日志包含排查编号、供应商、供应商用户 ID、本地用户 ID、邮箱、姓名、邮箱验证结果、准入/管理员判断、客户端地址、User-Agent、回调路径和配置 origin。

失败日志包含编号、分类、请求上下文及可获得的身份诊断。Google 邮箱拒绝明确记录邮箱与验证/准入判断；GitHub 记录候选邮箱及 verified/primary/allowed。身份尚未获取时不虚构邮箱或 ID。

记录异常链和堆栈，数据库补充 SQLState/错误号，HTTP 异常补充状态码；不输出 Token、授权码、Cookie、密钥、原始供应商响应或 SQL 参数。日志含个人信息，运维需限制访问、保留期限和外发范围。

### FR-11 一次性部署与 SQL

1. 完整工程部署一个 dp-admin 可执行 JAR，Vue 2 随包发布。
2. docs 提供 Linux systemd、Nginx HTTPS、Windows/IDEA、环境变量和文件目录配置说明。
3. 新安装 SQL 直接创建最终 users、oauth_identities、audit_logs 表，字段、索引、外键及检查约束一次定义，不拼接 ALTER 中间过程。
4. 3 张表、41 个字段均包含中文数据库 COMMENT。
5. 提供最小权限数据库运行账户模板，不预置账号或管理员密码。
6. 使用独立外部配置，避免继承仓库开发环境连接信息；部署手册包含验收、备份、恢复和排障。

## 5. 验收清单

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 两个供应商均未配置 | 页面无登录按钮并给出配置提示 |
| AC-02 | 任一供应商只配置 ID 或 Secret | 启动失败并指出配置不完整 |
| AC-03 | 已验证邮箱仅在 admin-emails | 可登录且能访问管理员路径 |
| AC-04 | 已验证邮箱仅在 allowed-emails | 可使用普通业务，管理接口 403 |
| AC-05 | 非名单、未验证或名单均为空 | 拒绝登录，不创建本地用户 |
| AC-06 | 邮箱大小写/首尾空格变化 | 精确归一化匹配；别名/通配符不扩大权限 |
| AC-07 | 匿名访问 API、业务 HTML、静态资源 | 分别 401、302、正常资源响应 |
| AC-08 | 伪造用户 Header 或旧 JWT | 不获得登录身份 |
| AC-09 | 缺失/错配/过期/重放 state、不同会话回调 | 拒绝登录 |
| AC-10 | 两个供应商相同邮箱 | 建立独立供应商身份，不自动合并 |
| AC-11 | 禁用或软删除已登录账号 | 后续到达业务校验的请求失效；不能重注册绕过 |
| AC-12 | 登录后数据库校验失败 | 503，不放行业务 |
| AC-13 | 缺失/错误 CSRF 的登录态写请求 | 403；正常上传/退出携带 CSRF 可执行 |
| AC-14 | 退出、Session 到期或服务重启 | 原会话无法继续访问业务 |
| AC-15 | 外域、协议相对或非法 returnTo | 回到默认文件管理页 |
| AC-16 | 登录成功/邮箱拒绝/数据库异常 | 日志含预期身份字段、错误分类和编号，不含密钥 |
| AC-17 | 新安装 SQL 一次导入 MySQL | 三张表及约束创建成功，全部表字段有注释 |
| AC-18 | 部署 HTTPS 站点 | 同域 API、Cookie 属性、回调与代理均符合配置 |

自动测试覆盖见技术文档。真实供应商登录、证书、目标文件权限、代理和生产数据库必须按部署指南实际验收，不能用单元测试替代。

## 7. 待办与后续建议

- 持续覆盖日志字段边界：真实邮箱、中文、Unicode 分隔符和超长字段，避免破坏诊断信息或注入伪日志。
- 对数据库连接获取和 SQL 执行分别计时，记录连接池等待情况；不能仅凭 23 秒健康检查判断网络慢。
- 将进程存活与业务就绪探针分离，采用轻量、有限超时的数据库检查。
- 修复历史文件路径校验问题并增加越界、符号链接及下载范围测试。
- 如有审计留存要求，将登录、退出、准入失败和管理操作接入持久化事件；制定脱敏和保留策略。
- 如需多实例，明确共享 Session、身份校验负载、密钥与 Cookie 策略后另行验收。


## 跨域请求支持
允许通过 auth.cors.allowed-origins 配置可信前端来源。合法浏览器预检匿名返回 200；实际业务请求仍必须满足登录、名单、权限与 CSRF 检查。默认不开放外部来源，禁止凭据搭配通配来源。跨域前端可读取 CSRF 响应头。
